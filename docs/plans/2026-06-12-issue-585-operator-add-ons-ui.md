## 1. Problem

The renter reservation wizard has a paid **add-ons** step (`AddOnsStep`, #460) and the
API is fully built — `packages/api/src/routes/add-ons.ts` exposes operator-private CRUD
(`GET/POST/PATCH/DELETE /add-ons`, `includeArchived`, auto operator-scope). But operators
have **no UI** to create or manage add-ons. The wizard's add-on step only shows seeded
rows; an operator cannot add "child seat", "ETC card", "snow tires", etc. This is the
last missing surface in operator pricing config.

## 2. Scope

**Web-only.** The API already exists and is unchanged. No schema, no migration, no API
edits. This is a UI port of the proven #530 insurance Vite pattern (cookie session +
react-query + CSRF), simplified for the add-on shape.

**Key shape difference from insurance:** add-on has a single **flat** `priceJpy`
(per-booking charge) — no `dailyPriceJpy`, no `deductibleJpy`. So `AddOnForm` drops the
deductible toggle entirely; it is just name / description / priceJpy.

## 3. API contract (already built — verified by reading the route)

`AddOn` store shape (`packages/api/src/stores.ts:238`), JSON-serialized (dates → ISO):
```ts
{ id, operatorId, name, description: string | null, priceJpy: number,
  status: 'ACTIVE' | 'ARCHIVED', createdAt: string, updatedAt: string }
```

Routes (`packages/api/src/routes/add-ons.ts`):
- `GET /add-ons?includeArchived=true&includeAll=true` → `AddOn[]` (name-asc). Reads are
  **management-role only** (`MANAGEMENT_READ_ROLES`; RENTER/PARTNER → 403). **Bypass-scope
  callers (PLATFORM_ADMIN, legacy STAFF/ADMIN) 400 unless `operatorId` or `includeAll=true`
  is sent** — same constraint #529 hit. Operator callers auto-scope server-side and ignore
  `includeAll`/`operatorId`. → client always sends `includeAll=true`.
- `POST /add-ons` → 201 `AddOn`. `FLEET_WRITE_ROLES`. Operator caller body =
  `createAddOnSchema` (no operatorId — stamped server-side).
- `PATCH /add-ons/:id` → 200 `AddOn`. Body = `updateAddOnSchema` (partial).
- `DELETE /add-ons/:id` → 200 `AddOn` (soft-archive: status → ARCHIVED).

Write validators (`@kuruma/shared/validators/add-on`): `createAddOnSchema`
(`name` 1–200, `description` nullish ≤2000, `priceJpy` int ≥0), `updateAddOnSchema`
(`.partial()`), types `CreateAddOnInput` / `UpdateAddOnInput`.

## 6. Gotchas (carried from #530 / #529)

- **CSRF:** cookie writes MUST send `X-CSRF-Token`. Use the insurance `writeJson` helper
  pattern (threads the header). Do NOT copy `operator-fleet/writeJson` — it omits the header
  (latent 403).
- **Bypass-role read 400:** send `includeAll=true` (see §3). Operators ignore it; bypass
  roles require it. This is the #529 lesson — `feedback_role-gate-not-just-ownership`.
- **routeTree.gen.ts:** regenerate by booting the dev server; never hand-merge.
- **i18n parity:** all keys must exist in en/ja/zh or the parity test fails. Verify after.
- **Biome:** re-read files after format; it sorts imports and may drop unused.

+ the insurance `useForm<z.input, unknown, z.output>` 3-generic shape, so the zod resolver coerces.

**i18n no-collision (N3):** existing `addOns` keys live only under `reservation.*` and `booking.detail`,
never under `business`. `business.addOns` + `nav.addOns` are additive in all 3 locales.
