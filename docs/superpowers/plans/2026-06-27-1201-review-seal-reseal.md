# Reviews Seal Reseal (#1201) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the denormalized-`operatorId` gap in the reviews seal by replacing the two overlapping unique seals with one airtight `UNIQUE (bookingId, subject)` that does not depend on a column whose correctness is only a service promise (#1201, Option 2).

**Architecture:** Today the operator-side seal is a *partial* unique index `(bookingId, operatorId, subject) WHERE authorRole='OPERATOR'`, plus a renter-side `UNIQUE (bookingId, authorUserId, subject)`. The partial index trusts the denormalized `reviews.operatorId` (no composite FK back to the booking's operator), so a writer setting a wrong `operatorId` could slip a duplicate operator review past it. `subject` is already CHECK-sealed to the author side (`reviews_subject_pairing_chk`: `authorRole='OPERATOR' ⇔ subject='RENTER'`) and there is exactly one renter per booking, so `UNIQUE (bookingId, subject)` is strictly stronger than both old seals and provably correct without `operatorId`. We replace both with the one constraint, collapse the two error constants into one, and mirror the single rule in the in-memory repo.

**Tech Stack:** Drizzle ORM + Postgres (drizzle-kit migrations), Hono API (services/repositories/pg-errors), Vitest (unit + real-pg integration via `test:integration`), Bun.

**Why this approach (FC/IS + DRY):** the uniqueness invariant moves from a *service promise* ("we always set `operatorId = booking.operatorId`") to a *provable DB invariant* over a CHECK-sealed column. Two overlapping seals collapse into one — fewer constraints, one error path, one in-memory branch.

**Source of truth:** issue #1201 (Option 2). Relates to #1158 (shipped seal via #1191, migration `0087`), #1187 (closed airtight-key PR — same approach, lost a merge race), #1085 (aggregate index reads `operatorId`).
