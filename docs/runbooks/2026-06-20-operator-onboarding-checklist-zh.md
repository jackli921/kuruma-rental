# 运营商接入 —— 签约前"残酷体检"清单

> 改编自一套 AI 落地的"残酷体检"打法。这份清单的目的不是帮你把运营商签下来,
> 而是**在最便宜的阶段(还没迁车队、还没承诺上线日期)就把死局筛掉**。在同意把
> 任何新的租车运营商接入平台(epic #385)之前,先跑一遍。
>
> 信号最强的一招:**要 3-5 条真实记录,不要描述。** 运营商嘴上说的数据成熟度,
> 永远比真实情况好看。他是爽快给你、支支吾吾、还是根本拿不出来 —— 这本身**就是
> 答案**。

## 1. 数据 —— 车队数据到底在哪

- [ ] 他们的车队 / 可租状态 / 价格数据现在在哪?是一个能直连的数据库,还是散在
      Excel + 一个老系统 + 员工脑子里?
- [ ] **拿 3-5 条真实车辆记录**(车牌、车型、价格、可租状态、照片、车检/保险
      到期日)。要真实导出,不是口头描述。
- [ ] 数据有没有人维护 —— 有没有指定的 owner 在更新,还是堆在那儿三年、字段含义
      都没人说得清?
- [ ] **APPI 红线(日本,碰不得):** 租客个人信息 —— 驾照、护照、#459 背后的证件
      上传 —— 在《个人情报保护法》下属于个人信息。在任何东西碰到它之前,先确认我们
      有合法依据持有并处理它。

## 2. 系统 —— 我们要对接的是什么

- [ ] 他们现在的预订系统是什么年代的?有没有 **API**,还是只有一个网页界面、底层
      数据库连文档都丢了?
- [ ] 谁掌握访问凭据,我们**到底什么时候能拿到**?
- [ ] **审批流程是日本项目的头号隐形杀手。** 接入需要走什么审批(IT、合规、运营商
      自己的管理层),实际要多久?技术上一天能干完的事,审批能让你等三个月。第一天
      就把这个时间问清楚、算进排期 —— 否则你的排期表从一开始就是假的。

## 3. 人 —— 到底谁在用

- [ ] 他们上线之后,谁的日常工作会被改变(柜台员工、调度、老板)?
- [ ] 这些一线的人知不知道这个项目?是支持、中立、还是抵触?
- [ ] **做之前能不能直接坐到一线员工旁边?** 如果运营商不让你接触一线,或者一线
      明显抵触,风险直接拉满:脱离使用者做出来的工具,就是个没人碰的摆设。

## 4. 预期 —— 成功标准(最容易被跳过,却是头号失败原因)

- [ ] 成功是不是被定义成一个**能量化、能验收**的指标(比如"人工重复预订事故 → 0"、
      "上架配置时间 2 天 → 2 小时"),而不是空泛的"提升效率"?
- [ ] 如果指标没达到,**Plan B** 是什么?
- [ ] 这事背后有真实的业务痛点驱动,还是只是一个"我们上了这个平台"的政绩?
- [ ] **把成功标准写进协议,写成一个我们能演示、能签字验收的东西。** 模糊的成功
      标准,是给项目最后撕逼埋的一颗雷。

---

**怎么读结果:** 这二十来个问题老实答完,一个接入能不能成,心里就有了八成谱。跑得
干净 = 推进。卡在 §1 拿不出样本、§2 审批时间是未知数、§3 不让接触一线 —— 在**承诺
之前**就把它们当成交易风险摊开来,而不是事后。
